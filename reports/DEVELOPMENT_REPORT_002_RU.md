# Отчет разработки №2 — 24.07.2026

## Название репозитория
`cdm-sequential-triage`

Display name: **Sequential CDM Triage**

Tagline: *Event-level risk-controlled triage for conjunction data message streams.*

Название описывает задачу, содержит основной поисковый термин CDM и не обещает предотвращение столкновений или эксплуатационную безопасность.

## Сравнение моделей на одинаковых development OOF-фолдах
Сравнены текущий `risk`, логистическая регрессия по текущему CDM, CatBoost по текущему CDM и CatBoost с динамическими признаками префикса. Calibration и evaluation не использованы.

Event-weighted prefix average precision:
- Logistic snapshot: 0,193;
- CatBoost snapshot: 0,371;
- CatBoost dynamic: 0,341.

На оптимистической frontier, где порог выбран по всем development OOF-событиям, CatBoost snapshot оказался лучше dynamic при α=5%: 56,13% против 46,46%. Dynamic немного лучше при α=10–20%: +0,56, +1,09 и +1,34 процентного пункта.

## Критическая проверка выбора порога
Проведена дополнительная cross-fitted проверка: для каждого фолда порог выбирался только на остальных четырех фолдах.

При целевом α=5% фактическая совокупная 95%-я верхняя граница составила 5,40% для logistic snapshot, CatBoost snapshot и CatBoost dynamic. Следовательно, ранее сообщенные 46,46% при upper bound 4,70% являются development-оптимизмом и не должны подаваться как устойчивый результат.

Cross-fitted результаты при α=5%:
- Current risk: coverage 10,31%, danger 2/192, UCB95 3,24%;
- Logistic snapshot: coverage 42,75%, danger 5/192, UCB95 5,40%;
- CatBoost snapshot: coverage 56,57%, danger 5/192, UCB95 5,40%;
- CatBoost dynamic: coverage 51,29%, danger 5/192, UCB95 5,40%.

При α=10% только CatBoost snapshot соблюл совокупную границу на development cross-fit: coverage 73,05%, danger 12/192, UCB95 9,93%. Dynamic получил coverage 73,99%, но UCB95 10,55%, то есть формально превысил цель.

## Решение по модели
Пока лидирует **CatBoost snapshot**, а не динамическая модель. Это важный отрицательный результат: добавление ручных агрегатов истории не обеспечило устойчивого улучшения на строгом участке frontier.

Динамическая гипотеза не отвергается окончательно. Следующий тест должен отделить:
1. недостаток качества динамических признаков;
2. неправильную функцию обучения на уровне отдельных префиксов;
3. реальное отсутствие дополнительной информации в истории относительно текущего CDM.

## Изменение протокола
До calibration требуется вложенный выбор порога или более консервативное правило с конечновыборочной поправкой. Порог, оптимизированный на тех же OOF-событиях, нельзя использовать для заявления о соблюдении α.
